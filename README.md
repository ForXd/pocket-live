# Pocket Live · 口袋片源

一个 Android 订阅播放器。**不内置、不分发任何订阅源、直播频道列表或视频播放地址；播放来源必须由用户自行添加。**

豆瓣推荐仅展示片名、评分和海报。点击推荐后，应用只搜索用户自己启用的来源，不从豆瓣获取播放地址。

## 安装与使用

从本仓库 Releases 下载签名 APK，支持 Android 8.0 及以上。

1. 在“订阅”页添加自己的订阅链接，按需启用来源。
2. 在“搜索”或“发现 → 订阅分类”中查找内容，打开详情后选择线路和集数。
3. 播放失败或卡顿时点击“快速换源”。优先显示当前来源的同集备用线路，再查询已启用来源中同名、同集的结果。
4. 可选择保留当前进度；不同剪辑版本的时间可能不完全对应。不按列表下标猜测集数，不会自动跳到别的剧集。
5. 网络不稳定时可开启“流畅优先”。多码率视频优先不超过 720p / 2 Mbps 的轨道；单码率视频无法凭空生成低清晰度，可尝试换源。

## 历史与应用更新

同名点播剧目会跨来源合并为一张历史卡片，继续观看默认使用最近一次来源和断点。展开后显示各来源的分集记录，删除整部剧会删除该组所有来源的历史。只统一空白、大小写和全半角，不去掉季数、年份等标题信息；直播仍按来源区分。标题相同但实际内容不同的资源可能归入同一组，可通过展开后的来源名称区分。

正式版启动或回到前台时检查 `ForXd/pocket-live` 最新正式 GitHub Release，每次运行至多每 24 小时自动检查一次；右上角“更新 / 有新版”可查看结果和手动重试。仅接受本仓库、对应版本、已上传的正式 APK 地址。点击“下载更新”交给浏览器下载，下载后打开 APK，由 Android 确认安装和签名兼容性。应用不后台下载或静默安装，更新包不占应用内部 50 MB 缓存预算。升级请保留原应用，勿先卸载。

发现页海报请求随页面前台生命周期执行，进入后台时取消，回到前台重试失败图片；刷新推荐也可重试海报。推荐刷新失败保留同一分类的已有内容，并显示重试入口；空列表、失败或超过五分钟的推荐在重新进入前台时检查刷新。推荐请求总时限 22 秒，包含排队时间。

## 播放与资源策略

- 点播预缓冲目标为 20–60 秒，首次起播阈值 1 秒、再次缓冲阈值 4 秒。媒体缓冲分配目标 32 MiB，不代表整个进程的内存硬上限。
- 缓冲较慢时提供重新连接和换源入口。临时加载错误最多重试两次；404 / 403 等明确失败不反复请求同一地址。
- 每次播放拥有自己的媒体请求集合。退出、换源、后台停止时先取消旧请求，再释放播放器；复用应用连接池，不为每次播放创建线程池。
- 备用来源查询最多检查 12 个已启用来源、同时查询 3 个，结果最多 40 条。关闭面板或切换播放会取消查询，旧结果不能覆盖新会话。
- 自写磁盘文件预算为 50 MB；视频不落盘。缓存可以在订阅页清理，订阅和历史保留。APK 和系统编译缓存不计入此预算。
- 可选的 HLS 广告过滤默认关闭，可能误判；复杂、加密、多码率或直播流保持原样。

片源服务可用性和持续带宽无法由播放器保证。豆瓣公开元数据接口也可能限流或变更。

## 订阅格式

`examples/subscription.json` 是空模板，不含任何地址。支持的来源字段和导入解析见 `SubscriptionParser`；不会执行来源里的脚本、网页解析或 DRM 解锁。

订阅保存在应用私有目录，系统备份已禁用。应用不上传订阅及观看历史至本项目服务器；导入、搜索与播放会按用户操作直接访问相应来源。推荐会访问豆瓣元数据和图片域名；更新检测会访问 GitHub 官方 Release API，不携带订阅或观看记录。

## 本地构建

需要 JDK 21、Android SDK Platform 37，以及 Android SDK Build Tools。设置 `JAVA_HOME` 和 `ANDROID_HOME` 后执行：

```sh
./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest assembleRelease
```

Release 默认不配置签名，私钥由开发者在项目外保存，通过 `apksigner` 签署产物。不要提交私钥、口令或用户订阅。

设备测试使用本地 MockWebServer 与测试媒体；真实豆瓣联网测试单独位于 `DiscoveryDeviceTest.liveDoubanAndCoverDecode`。测试 APK 的包名是 `org.streampocket.devtest`，正式包名为 `org.streampocket`。
