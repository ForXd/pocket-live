# v0.42.0 无边框按钮、全屏底部操作与预取预算

## 界面

按用户明确要求，移除共享文字 / 图标按钮、筛选标签、外观选项、选集与历史续播按钮的描边。保留轻微高光、半透明着色、选中底色和勾选，按钮不再依赖白色轮廓。输入框的焦点边界、弹窗外缘不是按钮，保留原有行为。

全屏顶部只保留返回和片名。上一集、选集、下一集、快速换源、更多选项集中到原生进度条下方的右侧操作区，左侧时间显示保留。隐藏该区域的原生重复按钮；播放 / 暂停、前后跳转和拖动时间轴继续由 Media3 处理。底部区与控制条同步显隐、横向空间不足时可滚动，并处理刘海安全区。原有右半屏玻璃面板和故障恢复入口不变。

## 预取预算与回收

普通设备单片上限从 2 MiB 提高到 32 MiB；当前交付、提升中的请求和下一片最多三个数组，即最多约 96 MiB 预取数据。实际按已知切片长度分配，不预先占满预算。未知长度才使用有界上限数组；超限回到正常读取。

同时按 Android 应用堆预算缩减单片限制：非低内存设备取 `min(32, memoryClass / 8)` MiB（最少 1 MiB）；标记为低内存的设备单片 4 MiB。32 MiB 的原有播放器样本缓冲、解码器及其他应用内存不包含在上述预取数据预算中，不能把 96 MiB 当成整个进程上限。仍只提前下一片、不写磁盘、不增加播放器。

暂停、停止、换源、后台和控制器释放时取消预取网络请求，并主动清空已完成 Future 中的字节数组，避免空闲协程调度线程间接保留大数组；继续播放后按需恢复。没有改动原有直播 / 加密 / 自适应多轨的绕过规则。

## 验证方式

新增 8 MiB 真实响应预取与弱引用回收测试，验证超过旧上限的切片可预取、暂停后数组可回收、暂停期间不启动后继请求、恢复后重新按需预取以及关闭后回收。该测试最初发现已完成异步结果保留数据，修正为显式清空 Future 结果后通过重跑。

播放器回归改为点击实际可见的底部“更多”入口，并断言操作区处于画面底部、低于时间轴中心，实际验证倍速、换源、500 集定位、切集与反复关闭窗口。截图及最终日志保存在 artifacts/v0.42.0/；发布身份及真正的应用内升级见 docs/releasing.md。

最终普通与 2 倍字号播放器回归通过；14 项设备回归、131 项单元测试通过。20 轮压力测试创建/释放播放器 56/56，残留弱引用与活动媒体 / 换源请求为零。结果限于已覆盖的模拟器环境。
