# v0.28.0 首页、分类与键盘修正

## 定位证据

先在 0.27.0 代码上新增并运行 `CatalogRegressionDeviceTest`，两项失败：选择悬疑未找到测试片库第 3 页的影片；输入时内容底部为 1163px，键盘顶边为 1499px，多留出 336px。测试日志存于忽略目录 `artifacts/v0.28.0/red.log`。

分类问题由两层逻辑共同造成：原实现只请求 `ac=videolist`，而标准 [MacCMS Provide 实现](https://github.com/magicblack/maccms10/blob/master/application/api/controller/Provide.php) 仅在 `ac=list` 等非详情请求中包含 `class` 分类表；缺少真实分类 ID 时回退为筛选首页，而同题材多 ID 又被当作不能映射。不能用 `wd=爱情` 代替题材查询，因为上游 `wd` 查询的是片名。

## 修正

- `CatalogBrowser` 先取得来源分类表，再按实际 ID 请求影片。爱情片、爱情剧等同题材多个分类分别查询并合并；随后继续检查综合片库中带题材标签的剧集，避免“爱情片”分类漏掉国产剧中的爱情剧；不猜数字 ID。通过实际分类 ID 补全缺失的分类名称，片名不参与题材推断。
- 无专属分类时按真实影片题材跨页查找。每批最多 4 个影片页、总超时 25 秒；找到 20 条可提前返回。游标保留下一分类和页码，继续查找不重扫已完成页。普通全部/原始分类浏览每批 1 页。
- 扫描范围不再停在前 10 页；单分类最多 1000 页、结果最多 1000 条，仍按批手动续查。空批次有后续页时显示继续查找，不声明整站无片。来源没有题材元数据时仍无法可靠推断，这是数据边界，不伪造命中。
- 切换来源、分类或关键词会取消旧任务，使用请求所有权阻止旧响应写回；重试后续批次复用游标，保留已加载内容。
- 键盘弹出时隐藏底部导航，并对 Scaffold 内边距调用 `consumeWindowInsets`，避免其与 IME 重复留白。按 [Android inset consumption](https://developer.android.com/develop/ui/compose/system/insets-ui#inset-consumption) 保留原生键盘动画。

## 设计与交互

本轮使用 Oil UI 的存量优化流程，沿用既有青绿、日夜配色和系统字体。产品方向为“一个搜索入口，选好题材即可浏览片库”。无生成图片，截图中的受控海报只用于测试。

- 推荐与分类共用固定顶部搜索框，分类模式搜索当前片库和筛选条件，移除第二个输入框。
- 来源和题材各为一个清晰入口；题材面板按行展开选项，选中后即时应用并收起，原始来源分类也可选。长来源名称可在来源面板查看。
- 首页续播卡更紧凑；电影/剧集选择并入标题行，排序收为有无障碍名称的按钮；推荐统一海报网格，移除重复的大推荐卡和说明。
- 复用原生按压、选中反馈、Material 底部面板动画、页面入场和列表动效，系统动画时长仍生效。

测试适配了真实的入口变更（统一输入、题材面板、卡片直接搜索、排序图标），保留原有数据与行为断言；新增分类协议与跨页测试，未通过删断言隐藏功能退化。
