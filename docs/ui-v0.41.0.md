# v0.41.0 局部玻璃材质与播放预取

## 设计方向

保留「幕间」暖黑 / 米白、现有字号与 8 / 12 / 16 / 20dp 圆角体系。根据用户后续要求，不为展示模糊效果添加大块背景。首页以海报、片名与评分为主，只在“查看简介”按钮内使用有界模糊海报；去除实验中的整块信息底板与导航装饰底板。保留原有简介 → 手动搜索片源流程。

参考用户提供的 [电影 App 列表](https://dribbble.com/search/movie)，实际查看 [Movie Streaming App UI](https://dribbble.com/shots/26941217-Movie-Streaming-App-UI-Design-Watch-Anytime-Anywhere) 的海报主导、开放信息布局和紧凑控件层级，并查看 [Tab & Segmented Control](https://dribbble.com/shots/25681273-UnifiedUI-Tab-Segmented-control-component) 的选中态。借鉴层级与克制边界，不复制其红色主题、账号或订票功能。参考图片仅用于本地设计审查，不打包到应用。

共享按钮增强细边框与轻微顶部高光；搜索框统一 12dp 圆角及轻边界，焦点加深。首页海报在日夜模式均使用浅色标题、暗色渐变遮罩，保证文字可读。装饰模糊层加载或失败时不显示破图图标。

浮层共享真实原生背景模糊（32dp，上限 120px）和半透明渐变材质，前景文字不模糊。普通模态窗额外柔化背景；全屏右半屏选集 / 换源 / 更多面板不模糊左侧视频。系统禁用窗口模糊时，打开浮层只读取一次最长边 320px 的背景图并在后台模糊，限定于面板内部。该降级是静态快照，不能宣称实时视频玻璃；截图失败则采用可读的渐变底色。不持续截图、不增加解码器；关闭窗口取消任务、解除监听、释放图片引用。

## 播放优化与约束

用户确认症状是频繁转圈缓冲。既有加载策略已是 50–60 秒目标储备及 32 MiB 媒体样本缓冲目标，本版保留它，不用无限扩大内存掩盖网络等待。

新增会话内 HLS 向前预取：读取当前切片的同时提前一个后续切片；播放需要它时提升同一请求并复用结果，不重复下载。只保留一项未请求的预取，可与当前读取并行；共用现有网络连接池和协程 IO 调度，不创建每播放器线程池或额外播放器。切换、后台、退出与解码器重建会取消所属网络请求、协程并清除引用。

- 单切片最多 2 MiB，低内存设备 512 KiB。固定数组读取，不用扩容 / 全数组复制；当前交付、等待中的切片和后继预取合计最多三个这样的数组（普通设备最多 6 MiB 数据数组，低内存最多 1.5 MiB）。另有播放器原有缓冲、网络缓冲和有界 URL 索引；不能把 6 MiB 当作整个播放器内存上限。
- 预取请求绝对超时 8 秒。失败、超限或不适用时交还正常加载，并停止本会话后续预取。完整读取成功才交付，截断数据不进入缓存。
- 仅单一路径、音视频复用、未加密且有结束标记的点播 HLS；多码率自适应与独立音轨/字幕保留原带宽统计及加载；直播、DRM / AES、字节范围、初始化切片、多于 2000 切片或 URL 合计超过 262144 字符的列表不预取。MP4 等维持原加载方式。无磁盘缓存、整集下载、下一集后台下载。
- 使用广告过滤后的已解析列表，避免预取已删除的广告切片。URL 和重定向仍经过现有网络策略。
- 并发可隐藏响应等待，不能增加运营商或片源的总带宽；总带宽低于媒体码率时仍需原有流畅模式或换源。

## 可重复验证

`PlaybackPrefetchDeviceTest` 的首个基线使用原始 OkHttpDataSource：每次响应延迟 600ms，三个切片与相同的消费间隔共约 3800ms，超过 3200ms 验收线。接入预取后约 2.6 秒且仍为三次请求。

真实 HLS 播放差分测试：每个切片首响应延迟 2300ms，播放至 8 秒，原路径触发一次二次缓冲，预取路径为零。两个分支使用同一视频和同一软件解码器，隔离 API 37 模拟器 goldfish H.264 的 CSD 错误；生产原有运行时解码器恢复由完整播放器回归覆盖。该受控网络测试不是用户设备或所有外部片源的速度保证。

另验证直播及加密列表不投机读取、超大切片回到正常路径且停止预取、阻塞请求关闭后归零。共享玻璃测试验证最长边 320px、模糊效果与原始海报缓存不被修改。

最终截图及测试日志在本地 `artifacts/v0.41.0/`。独立存量视觉复核已确认暗色首页、搜索和弹窗：去掉大板后海报重回主角、局部 CTA 模糊可见、无装饰缺图图标。浅色、2 倍字号、宽屏与全屏播放器也通过静态复核，无阻断可读问题。各页面操作可达性、500 集定位、倍速切换与反复打开/关闭面板由设备测试另行覆盖。完整播放专项最终 11 项通过，20 轮压力测试创建/释放播放器 54/54、弱引用和活动媒体/换源请求为零；这些结果不代表所有真实设备或外部片源。其他发布验证记录在 docs/releasing.md。
