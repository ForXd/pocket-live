# 播放会话与换源

`AppModel` 保存轻量播放数据与有界历史；`PlaybackController` 持有本次播放器、媒体请求和采样任务，UI 负责在生命周期停止或离开时释放它。

换源查询以当前 `sessionId` 和递增的 owner 标记为归属。取消时先更换 owner，再取消协程；即使旧请求较晚返回，也不能修改新的候选结果或当前播放。结果只持有视频元数据与一个集数，不缓存每个来源完整的选集列表。

选择备用地址会生成新的播放会话。旧会话的最终历史检查点可被保存，但不能覆盖新会话状态。切换前从播放器读取最新进度；只有用户保留进度时才传给新会话。集数按名称或明确的数字标签匹配，不以数组位置推断。

媒体网络层 `MediaCallOwner` 复用应用的 OkHttp 连接池和调度器，只追踪自己创建且尚未结束的请求。结束与取消都会移除请求。集合添加、移除和快照统一使用短锁；实际取消时不持有该锁，也不关闭共享执行器，避免交叉取消或阻塞另一个查询。播放器释放前先取消媒体请求。

播放器状态、Media3 回调和 UI 操作均在主线程；网络、解析、磁盘操作在对应的 IO 或后台执行器中。每个播放器只有一个有界采样循环，在暂停到后台或关闭时取消。所有旧播放器回调先核对实例归属。

内存及死锁验收采用反复换源、并发查询取消、后台恢复、计数守恒、弱引用回收、托管堆/PSS 采样与释放耗时。测试通过是给定环境下的证据，不是所有设备、解码器和网络上绝对无泄漏或死锁的数学证明。
