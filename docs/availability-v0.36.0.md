# 0.36.0 来源状态、播放探测与浏览交互

## 行为与边界

- 订阅来源使用原搜索健康缓存：绿=最近搜索成功、红=最近搜索失败、黄=待验证/记录过期。每个订阅内成功优先、未知居中、失败在后。颜色同时配文字；不会把接口成功当作该来源所有影片都能播放。沿用成功 7 天、失败 30 分钟 TTL，回到订阅及应用前台时重新取有效快照。
- 关键词搜索自动检查相关点播结果的第一条非空线路首集。只验证媒体可达和容器前缀：HLS 需读取有效列表并沿相对 URI/重定向读取首个片段，MP4/TS 需媒体结构前缀；HTTP 200 HTML 不通过。加密 HLS、DASH 等不能可靠判断时保留“待确认”。“媒体可用”不是全剧集解码或连续播放保证，未探测结果仍可手动打开。
- 找到两个媒体可用结果即停止自动探测并置顶，不丢弃其他搜索结果、不停止其他来源的正常结果收集。最多 12 个候选、30 秒总限、单项 5 秒；独立通道串行请求，不占搜索的四并发槽。每次媒体读取最多 64KiB，递归深度最多 2（主列表→子列表→片段）；详情沿用 2MiB 上限。
- 探测不创建播放器、不出声、不写观看历史、不改变来源搜索健康。仅缓存最多 100 个 source hash / video id 状态，5 分钟 TTL，不持久化媒体地址；换查询、离开搜索页、应用后台均取消，旧会话不能写新结果。低内存时清缓存，ViewModel 销毁时关闭独立网络通道。
- 历史查询复用首页折叠控制器：上滑隐藏搜索框、下滑显示，键盘出现时固定展开；原筛选、历史和保存槽位保持。
- 分类下拉会在当前来源/题材/关键词约束下获取分页范围并选择随机有效页，替换为新的随机排列结果。未知总页仅查询第一页，不猜测无效页；无新匹配时保留并随机排列已有结果，界面明确提示。批次 30 秒、每源 10 秒、4 并发、最多保留 1000 条，不绕开用户筛选。

## 设计与验证

沿用青绿 Material 搜索/卡片规范，来源健康以色点+文字呈现；搜索摘要直接说明探测中或找到两条后停止。独立静态视觉评审通过（不打分），测试夹具订阅时间为 epoch 不代表真实用户数据。截图与过程测试保存在本地 artifacts/v0.36.0。
