# v0.20.0 · 首页与设置导航参考

调研日期：2026-11-02。本文记录官方资料及本项目的设计取舍，不宣称复刻商业 APP 的现有界面。

## 可借鉴的操作层级

| 官方依据 | 可落地的原则 |
| --- | --- |
| [Android 搜索栏指南](https://developer.android.com/develop/ui/compose/components/search-bar)将搜索栏描述为持续可用的关键词输入入口，适合搜索是核心任务的应用。 | 首页顶部保留搜索栏，放在推荐/结果滚动容器之外；输入和搜索结果使用同一页，避免重复导航。 |
| [Android 布局与导航指南](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns)建议同级主目的地使用 3–5 项导航，并将页内标签作为次级导航；大屏通常改用侧边导航栏。 | 手机底部采用“首页、订阅、历史、设置”四项。推荐/分类筛选留在首页内容区，设置始终是最右一项。 |
| [Apple TV 官方推荐帮助](https://support.apple.com/en-euro/guide/tv/atvb0916ba14/tvos)说明用户可以从 Home 的推荐行浏览内容，也可以在 Search 输入关键词后通过电影/剧集分类浏览相关内容。 | 借鉴内容推荐与定向查找相互衔接的组织方式。首页保留继续观看、推荐列表和分类；点推荐可直接发起同页搜索，不切到另一个底部目的地。 |
| [Spotify 搜索帮助](https://support.spotify.com/us/article/search/)把搜索用于寻找多种内容；[Spotify 设置操作帮助](https://support.spotify.com/us/article/change-language/)把显示语言等偏好集中在 Settings and privacy 的分类中。 | 搜索入口服务找片任务，外观、网络、缓存和版本更新集中到独立设置页，首页不再重复放齿轮和更新按钮。 |

## 本项目选择

合并首页、固定顶部搜索和右下角设置是本次用户明确提出的结构。Apple TV、Spotify 的官方资料并未要求“搜索与发现必须同页”或“设置必须右下角”；这里采用的是它们的任务分组思路，具体导航位置服从本次需求。

首页默认显示推荐。提交关键词后，搜索栏仍停留在原处，内容区变为加载状态、结果或无结果说明；必须提供明确的“返回推荐”路径。进入详情再返回，应回到进入详情前的首页模式。搜索任务退出时取消旧任务，避免后台结果把已回到推荐的页面重新切成结果页。键盘搜索键和可点击搜索按钮执行相同行为。

设置页建议依次排列外观、应用更新、播放与网络、存储与缓存、关于与许可。更新卡片显示当前版本和检查/下载状态，下载流程继续沿用现有校验及安装确认。订阅页专注添加、替换、启停和删除来源；订阅更新仍属于该订阅自身的内容管理，不与应用版本更新混为一谈。

大屏的官方默认建议是侧边导航栏，但用户要求设置固定右下角。实现时应明确取舍并保持入口位置可预测，不能只为了照搬某个示例而把设置移到难找的位置。播放器全屏仍应优先保证观看与返回操作，避免把应用设置长期覆盖在视频上。

## 验证重点

- 推荐列表长距离滚动后搜索栏位置不变；键盘出现时输入和提交仍可达。
- 空关键词不发请求；取消搜索、返回推荐、返回详情和切换主目的地行为一致。
- 搜索结果与推荐的筛选/排序保持各自语义，不把推荐排序误用于全源搜索。
- 设置在主页面右下角可达；外观、应用更新、网络和缓存入口已迁移且不再散落于顶部或订阅页。
- 大字体、窄屏、横屏和宽屏中的固定栏不遮挡最后一行内容；主导航有文本标签，触控目标不小于 48dp（本项目既有约束）。
